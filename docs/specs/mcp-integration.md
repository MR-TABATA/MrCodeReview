# MCP によるコーディングエージェント双方向連携

- 作成日: 2026-11-19
- 状態: 下書き

## 目的
MCR のレビュー指摘をコーディングエージェント（agy、Claude Code、Copilot 等）と双方向に同期し、Terminal 窓が勝手に開く騒々しさや、修正結果の手動取り込みの手間をなくす。

## 決めたこと
- 観点ごとの 1 発起動ボタンを廃止する
  - なぜ: 観点ごとに Terminal 窓が次々と起動されるのはうるさく、同じファイルに対する同時修正で競合するリスクもあるため。
- MCP（Model Context Protocol）による双方向連携（DB 共有）を採用する
  - なぜ: MCR とエージェント間で同じ SQLite DB を共有し、エージェントが修正完了時に自動で DB に書き戻すことで、手動での「取り込む」ボタンを不要にするため。
- レビュー役と修正役のエージェントを自由に組み合わせ可能にする
  - なぜ: 「agy でレビューして Claude Code で修正」「Claude でレビューして agy で修正」「Copilot で修正」など、どのエージェントでも MCR のローカル DB を共通ハブとして扱えるようにするため。
- agy、Claude Code、Copilot の各エージェントで MCP 連携できるようにする
  - なぜ: 普段使うどのエージェントからでも同じように MCR の指摘を扱えるようにするため。

## やらないこと
- 観点ごとの Terminal 自動起動
  - なぜ: 観点ごとに起動されるのはうるさいため。

## タスク
1. `mrcr` CLI に Stdio 型 MCP サーバー機能（`mrcr mcp` コマンド）を追加する
   - 触るファイル（見込み）: `crates/mrcr/src/main.rs`, `crates/mrcr-core/src/handoff_api.rs`
2. MCR の画面から観点ごとのワンクリック起動ボタンを廃止し、MCP 連携案内またはまとめプロンプトコピーへ整理する
   - 触るファイル（見込み）: `app/src/main.ts`, `app/src/handoffview.ts`
3. 各エージェント（agy、Claude Code、Copilot）向けの設定手順の整理、および設定コマンド（`mrcr mcp setup` 等）の検討・追加
   - 触るファイル（見込み）: `crates/mrcr/src/main.rs`

## 受け入れ基準
- `mrcr mcp` が起動し、MCP クライアント（agy や Claude Code）からツール一覧が認識されること（確かめ方: `~/.gemini/config/mcp_config.json` 等に登録し、エージェントからツールが見えることを確認）
- agy または Claude Code から指摘一覧が取得でき、修正完了を記録すると MCR の DB に反映され画面で「対応済み」になること（確かめ方: エージェントで修正・報告を実行し、MCR の画面で手動取り込みなしに対応済みになることを確認）
- MCR の指摘画面で、観点ごとの勝手な Terminal 自動起動ボタンが表示されないこと（確かめ方: 画面でボタンがなくなっていることを目視確認）
