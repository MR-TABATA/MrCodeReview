# コードからの仕様・前提・フロー逆抽出（リバースエンジニアリング）

  ```
  cd /Users/hitoshi/Git && agy --resume c0d32c51-09ef-48a7-90b6-5a5ceffa91fd
  ```

## 目的
コード（Git の差分およびファイル全体）、および将来的なバイナリ・ビルド成果物から、業務ルール・暗黙の前提・データフローを逆算して抽出し、画面でのインスペクト（理解・吟味）およびドキュメント（仕様書・PR 文面）としての出力を可能にする。

## 決めたこと
- MCR にコードのリバースエンジニアリング機能を導入する
  - なぜ: （会話に理由なし）
- 対象は「Git の差分（PR・コミット）」と「ファイルやモジュール全体」の両方とする
  - なぜ: 差分から変更仕様を把握する需要と、既存コードから失われた仕様を逆引きする需要の両方があるため。
- 抽出する内容は「業務ルール・不変条件」「暗黙の前提・落とし穴」「データフロー・振る舞い」の 3 つとする
  - なぜ: コード理解には仕様・制約・処理の流れがセットで必要なため。
- 抽出結果には MCR のコード原文引用照合（evidence）を適用する
  - なぜ: AI のハルシネーションを排除し、コードの事実に基づいた裏付けを保証するため。
- 出口は「画面での表示（インスペクタ）」と「ドキュメントとしての出力（仕様書保存・PR 文面コピー）」の両方とする
  - なぜ: 画面で理解・吟味（インスペクト）し、納得したものをドキュメントとして固定化（出力）する一連のワークフローのため。
- 観点はモジュール化して分ける（業務ルール、暗黙の前提、データフロー）
  - なぜ: 1 つのプロンプトに詰め込むと浅い要約になるのを防ぎ、必要な深さを選択できるようにするため。
- 段階的に進める（Phase 1: レシピ追加 ➔ Phase 2: 出口機能追加 ➔ Phase 3: ファイル全体解析 ➔ Phase 4: 成果物・バイナリ解析（REA連携））
  - なぜ: 既存の MCR 資産（Git差分）を活かして小さく始め、将来的にはソースコードのないレガシーアプリや成果物からの仕様逆引きにも広げるため。

## やらないこと
- 外部 Web サイト等のスクレイピング＆レポート生成機能
  - なぜ: まだ理論上の話であり、実務の切実な需要が検証されていないため。

## タスク
1. MCR の `recipes/` にリバースエンジニアリング用の観点レシピ（業務ルール、暗黙の前提、データフロー）を作成する
   - 触るファイル（見込み）: `recipes/` 配下の新規 Markdown ファイル
2. 既存の差分に対してレシピを実行し、カードの引用照合と内容が実用レベルか検証する
   - 触るファイル（見込み）: 未定（実リポジトリでの手動検証）
3. 画面に「PR 文面コピー」および「仕様書（`docs/specs/`）書き出し」の出力ボタンとテンプレートを追加する
   - 触るファイル（見込み）: `app/src/` 配下のフロントエンドコード
4. ファイル全体の解析（全行差分扱い等の入力対応）を検討・実装する
   - 触るファイル（見込み）: 未定
5. （Phase 4 見込み）REA（morluto/rea）等のリバースエンジニアリング MCP / CLI と連携し、バイナリや Electron / .NET アプリからの仕様逆抽出を検討・検証する
   - 触るファイル（見込み）: 未定

## 受け入れ基準
- MCR でリバースエンジニアリング観点を選択して実行したとき、コード引用行を伴う仕様・前提・フローのカードが表示される（確かめ方: MCR で実行し、カードと引用の表示を目視確認する）
- 選択したカードから仕様書 Markdown または PR 文面が生成・コピーできる（確かめ方: 出力ボタンを押し、クリップボードまたは保存されたファイルの内容を確認する）
