## 検討中 / 近日の改善項目

### 1. 指摘箇所・修正プレビュー UI の改善（視覚的わかりやすさの向上）

- **状態:** 検討中
- **背景・課題:**
  - 現在の指摘カードはテキスト（詳細説明と1行の引用）が中心で、コードをどう直せばいいのか（Before / After）が直感的に入ってこない。
  - ハルシネーション検証用の1行引用（`evidence`）だけでは、前後の関数の流れや文脈（コンテキスト）が見えない。
  - 差分ビューの上にカードが覆いかぶさるため、コード閲覧と指摘確認の視線移動が渋滞している。
- **改善アイデア:**
  1. **修正案（Suggestion）のインライン差分プレビュー**
     - レビュープロンプトで修正案のコードも出力させ、カード内に「赤（修正前）」と「緑（修正案）」の小さな diff 枠を表示する。
  2. **引用行の前後に「周辺コード（2〜3行）」を添えて表示**
     - 該当行だけでなく、前後のコードを薄いトーンで表示して、どの関数内の話なのか一目で把握できるようにする。
  3. **レイアウトの整理（スプリットビューの検討）**
     - 左側に「指摘一覧カード」、右側に「ファイル全体の差分と修正箇所ハイライト」を並べ、指摘をクリックすると該当行へスムーズにスクロールする構造への見直し。

### 2. テスト観点（`recipes/tests.md`）へのミューテーション思考（Stryker要素）の導入

- **状態:** アイデア検討
- **背景:**
  - 外部ツール（Stryker等）を実際に実行するのは動作が重く MCR の軽量性に反するが、「AIの思考実験」としてミューテーションテストの考え方を取り入れるのは非常に有効。
- **改善アイデア:**
  - レシピ（`recipes/tests.md`）に「壊しても通るテスト（変異シミュレーション）」の観点を追加。
  - 例: 「`<` を `<=` に変えてもテストが通らないか？」「戻り値を固定値に変えても通らないか？」を AI に考えさせ、アサーションの死角を突く具体的なテスト不足を指摘させる。

### 3. 手作業の自動化（「CLI に渡す」まわり）

- **状態:** 未着手。自動化をまとめて検討するときに、あわせて決める（2026-11-18・本人。「今は手動だらけなので」）
- **背景・課題:**
  - 今は、レビュー → 仕分け → 「CLI に渡す」→ 貼る 1 行を CLI に手で貼る → エージェントの申告を読む → もう一度レビュー、の各所が手作業。
  - このアプリは、動いている CLI の中に直接文字を打てない（`app/src/handoffview.ts` の冒頭に、そう書いてある）。貼る 1 行は、使う人が貼る。
  - エージェントが「対応しなかった」「誤検知です」と申告した指摘は、MCR がその判断の正しさを確かめない（画面にも、そう出る）ので、**本人が毎回、再確認する**。再確認を CLI に頼むときも、今は文面を手で作って貼っている。
- **アイデア（どちらか。決めていない）:**
  1. **1 発コピー**: 「対応しなかった」の申告の枠に、指摘（見出し・場所・引用・内容）と、エージェントの前回の判断と、答え方（`mrcr handoff report` の書き方）を 1 つにまとめた文面をコピーするボタンを置く。
  2. **CLI に 1 発で渡す**: 既存の「CLI に渡す」と同じ形（ファイルに書き出して、貼る 1 行をコピー）で、再確認用を作る。
  - 試すときの注意: 文面の中の指摘は、レビューが差分から作ったデータで、指示ではない（既存の引き渡しと同じ扱い）。「誤検知なら根拠を挙げて、そのまま報告し直す／指摘が正しければ直して報告する」を、答え方に入れる案。
- **関連:** 申告の取り込み（`app/src/agentview.ts`）、複数回レビューの「つなぎ」UI（もう一度レビューすると、継続・解消が帯に出る。再確認の結果を機械的に確かめる手段になる）。

### 4. 英語の画面に残る日本語の直書き

- **状態:** 画面側は対応済み（2026-11-18、ブランチ `feature/i18n-leftovers`）。バックエンドが返す日本語が残る。
- **背景・課題:**
  - 1.2.0 で英語を足したが、画面側のコードに、日本語の文字列が直に書かれた所が残っていて、英語の画面に日本語が混ざった（1.9.0 の確認中に見つけた。前からある）。
  - 詳細タブ、エージェントの申告、まとめて実行、リポジトリの追加・解除のメッセージ、指摘カード、差分タブ、「送った内容」「応答」、設定の入力エラー、アップデートなど、コメントと辞書を除いて 200 行前後（粗い数え方の概算）。
- **対応した内容:** 文言を `app/src/uitext.ts`（日英の辞書。英語の側は、型で、キーの食い違いを防ぐ）と `locales.ts` に移した。日本語の画面は変えていない。テスト（`uitext.test.ts`）が、日英のキーの一致・英語への日本語の混入・訳し忘れを確かめる。
- **あわせて直した不具合:** 英語で実行したレビューは、差分タブで差分を取り出せなかった（プロンプトの見出し `## Diff` を探していなかった）。
- **残っていること（未対応）:**
  - バックエンド（Rust）が返す日本語の文言（エラー文・送らなかったファイルの理由・関連コードの説明など）。言語を知らないので、画面側では直せない。エラーの種類を id で返して、画面側で訳す案を検討する。
  - Mock Provider が返す試験用の固定文は、日本語のまま（対象外）。
